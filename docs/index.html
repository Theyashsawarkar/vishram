Vishram (विश्राम) is Sanskrit for "rest": the rest at the end of a session: lock, suspend, power off.

vishram is the power menu for Vyom: one keyboard-driven panel that opens instantly, with live data, a preview and a key for everything. It runs on any compositor with the layer-shell protocol (sway, Hyprland, river, niri, Wayfire, labwc…). In Vayu, the desktop it was built for, it replaces nwg-bar.

#Features

  • Lock, suspend, log out, reboot and power off as big tiles, one key each (Lock has the focus, so Enter; then s e b p): the safe ones (lock, suspend) apart from the final ones (log out, reboot, power off). h / l and Enter work too, with an accent frame on the tile you're on; Space never presses a tile.
  • Log out, reboot and power off count down 5 seconds first: the tile's icon becomes a red ring that fills, with a red notice ("Powering off in 3 s"). Any key cancels; Enter does it now.
  • Warns about unsaved work on sway: windows whose titles say they have unsaved changes (*notes.txt, ● main.py, [+], "unsaved", "(modified)") are named in the notice; otherwise it says how many windows will be closed. Apps that don't mark their titles (LibreOffice, for one) can't be seen this way.
  • Log out works on sway, Hyprland and niri out of the box (else loginctl terminate-session).
  • Keyboard first: every action has a key, shown in the footer; the mouse works too.

#Install

#Requirements

  • Vyom 0.6.0 or newer (Python 3.11+, PyGObject, GTK 4, gtk4-layer-shell, a Nerd Font)

#Install

git clone https://github.com/Theyashsawarkar/vishram ~/.local/share/vyom/plugins/vishram
vyom reload           # pick it up (or log out and in)
vyom vishram            # open it; run it again to close

Give it a key in your compositor, e.g. sway:

bindsym $mod+<key> exec vyom vishram

#Update and uninstall

git -C ~/.local/share/vyom/plugins/vishram pull && vyom reload     # update
rm -rf ~/.local/share/vyom/plugins/vishram && vyom reload          # uninstall

#Usage

Open it with vyom vishram (or your key). It's always in NORMAL mode (there's nothing to type): Lock has the focus when it opens, so Enter locks; s suspends, e logs out, b reboots and p powers off. h / l (or j / k, the arrows) move between the tiles and Enter picks the one you're on. Log out, reboot and power off count down first: Enter does it now, any other key cancels, Space included. Space alone is the leader (Space ? lists every key); it never presses a tile.

Vyom's vim keys work too: ? and Space ? list every key, Space Space is the palette, q closes, Esc steps back, Space u f is fullscreen, Space r refreshes; on a card j / k move between controls, h / l change the focused one and Enter presses it.

Keys (it's always in NORMAL mode: there's nothing to type)

KeyAction
sSuspend
eLog out (after a 5-second countdown)
bReboot (after a 5-second countdown)
pPower off (after a 5-second countdown)
EnterPick the focused action (Lock has the focus when the menu opens)

While a countdown runs

KeyAction
EnterConfirm the action now instead of waiting
EscCancel the countdown (any other key does too, Space included)

Keys that moved in this release still say where they went: r → b (reboot), L → Enter (Lock has the focus).

#Configuration

Everything is optional, in ~/.config/vyom/config.toml under [plugin.vishram]:

SettingDefaultWhat it does
lock / suspend / logout / reboot / poweroffloginctl lock-session, systemctl …The command for each
countdown5Seconds before log out / reboot / power off

Run vyom reload after editing.

#Troubleshooting

  • Nothing opens. vyom list shows every installed tool, and why one is skipped (a missing requirement, or a Vyom that's too old).
  • It opened, then something failed. Look for a Traceback in the daemon's log, journalctl --user -u vyom -u vyom-daemon -b (without systemd: ~/.local/state/vyom/daemon.log), and open an issue with it.
  • No blur or rounded corners. That's the compositor: on SwayFX, add layer_effects "vyom" { blur enable; corner_radius 20; shadows enable }.
